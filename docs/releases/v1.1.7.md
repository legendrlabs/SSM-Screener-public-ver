# SSM v1.1.7 — Work/Codex CLI startup and update-check reliability

v1.1.7 changes the **CLI bootstrap and release-check path**, not the SEC
screening logic, model gates, WATCH/PASS criteria, or current share arithmetic.

## Fixed

- Importing `ssm.cli` and running `--help` no longer eagerly loads scanner,
  SEC provider, market provider or `requests` packages.
- `ssm version --offline` works using Python 3.11+ standard-library modules
  only and reports the installed version with `update_available=null`.
- Online `ssm version` fetches immutable GitHub Release metadata using Python's
  standard library with an 8-second per-request timeout and a single retry for
  transient errors. A timeout returns `latest=null`,
  `update_available=null`, and a specific `check_error`; it is **not**
  reported as confirmation that an upgrade is unnecessary.
- `scripts/prepare_runtime.py --venv "<TASK_DIR>/.ssm-venv"` creates an
  isolated environment **outside the mounted skill directory** and checks
  the bundled dependency installation. A writable scratch workspace and
  PyPI access are required. The helper never runs a scan or performs an
  engine update.
- Release asset download URLs are required to point to the official repository.
  Immutable commit-pinned archive, SHA-256 manifest, rollback and user-state
  preservation protections remain active.

## Use from an installed skill

Local diagnostics without third-party dependencies:

```bash
python "<SKILL_DIR>/scripts/run_ssm.py" --help
python "<SKILL_DIR>/scripts/run_ssm.py" version --offline
python "<SKILL_DIR>/scripts/run_ssm.py" version
```

If `scan`/`check` dependencies are absent in the current session:

```bash
python "<SKILL_DIR>/scripts/prepare_runtime.py" --venv "<TASK_DIR>/.ssm-venv"
"<TASK_DIR>/.ssm-venv/bin/python" "<SKILL_DIR>/scripts/run_ssm.py" version
```

On Windows the venv interpreter is under `Scripts/python.exe`.

The **currently mounted Work skill** is not replaced automatically by this
GitHub release. Inspect the actual installed SKILL.md root and verify the
updated entry point using that installed path after explicit upgrade approval.
If GitHub is unavailable, report UPDATE_CHECK_FAILED and continue on the
known local version only if it is safe to run.

## Compatibility and tests

- Tests verify bare Python with `python -S`, as well as mocked Release
  failures, bounded retries, official asset URL restrictions and installation
  directory protection.
- There is no public SEC scan or centrally published market output.
- `config/watchlist.csv`, `config/overrides.json`, `output/` and
  `SEC_USER_AGENT` remain private and user-managed.

The Release workflow must pass Python and Node test suites and publish
the immutable `v1.1.7` tag and `release.json` asset pinned to its
tested source commit.
