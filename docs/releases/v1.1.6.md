# SSM v1.1.6 — distribution-only release

This is the first formal release of the **distribution-only** policy after
the v1.1.5 unified Python engine. The screening rules, conservative gates and
SEC filing verification behavior are unchanged.

## Changes from v1.1.5

- Canonical public repository distributes the `SKILL.md`, bundled Python engine,
  tests, configs and immutable updates; it does not execute a central SEC scan.
- Removed the central scheduled GitHub Action, central scan-output publisher,
  scan trigger and associated tests. CI and release automation remain.
- Every recipient configures **their own** `SEC_USER_AGENT` inside their own
  runtime before live `scan` or `check`. This is an SEC HTTP contact identity,
  not an SEC password or token.
- Added user-specific setup guidance and protections against treating the
  upstream repository's empty `output/` as a current research signal.
- Updated release strategy, README, updater documentation and the skill instructions.

## Upgrade

Installations that support the bundled updater:

```bash
ssm version
ssm update
ssm version
```

For a ChatGPT/Codex managed skill, the runtime must be able to access the complete
installed skill bundle; updating the Python CLI alone does **not** register it.
Before requesting live scans, configure `SEC_USER_AGENT` for **the current user**
in that environment. Keep this value out of the public repository and logs.

For the complete procedure, see [UPDATING.md](../../UPDATING.md) and
[User SEC setup](../operations/user-sec-setup.md).

## Security and compatibility

- `config/watchlist.csv`, `config/overrides.json`, `output/` and the
  process `SEC_USER_AGENT` remain user-owned and are preserved by the updater.
- Previous tags and release manifests are immutable.
- A missing live scan is `DATA_HOLD`, not `NO CANDIDATE` or `PASS`.
- A public GitHub Release has no global/central SEC credentials.

## Release verification

The release workflow must pass Python and Node tests, publish an immutable
`v1.1.6` tag and include an asset named `release.json`, whose
`source_commit` matches the tag target commit.
